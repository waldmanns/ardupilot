# Additive VSP roll stabilization

VRS adds short, fixed-direction control-rod corrections to the maneuvering
command **after** each VSP's existing `mapCoordinates()` ring limiter and angle
correction. Maneuvering continues during a burst. RPM passes through unchanged.

`VRS_ENABLE=0` is the compiled default and a strict behavioral bypass: original
X/Y/RPM outputs, original named-float telemetry only, and no VRS AHRS reads or
filter/geometry processing. Disabling during a burst removes the correction on
the next routing cycle, with no ramp-down tail. Existing parameter storage IDs
and routing behavior are unchanged.

## Direction and roll effect

Each drive has one ray in its **post-limiter component coordinates**:

| Angle | Added displacement |
| --- | --- |
| 0 | +X |
| 90 | +Y |
| 180 | -X |
| 270 | -Y |

These are not compass bearings or automatically bow/starboard/stern/port. Set
each ray to produce the intended physical lateral thrust after the installation's
linkage, routing and PWM scaling/reversal. `THR_ANG` is already applied to the
maneuvering command and is **not applied again** to the VRS vector.

`VSPn_RS_SIGN` describes the roll moment generated by positive movement on that
ray: -1 produces negative body roll, +1 produces positive body roll, and 0
excludes the drive from VRS. With correct AHRS orientation, positive roll is
normally starboard down. Establish the actual effect for each installation.
Two configured drives must have opposite signs; a single drive is permitted
for commissioning. A sign setting selects a drive, never reverses its vector.

Direction is guaranteed at the component output, to integer PWM resolution.
Any downstream axis swap, scaling, inversion or additional VSP component changes
the physical mapping and must be included in the installation calibration.

## Controller and authority

One controller samples EKF roll and the AHRS bias-corrected body X gyro rate once
per routing cycle. Rate uses a first-order low-pass filter. The requested signed
correction, in fractions of ring radius, is:

```text
demand = constrain(-P * (roll_deg - trim_deg) - D * filtered_rate_dps, -1, 1)
```

The demand deadband has hysteresis: enter above `DB`, release at or below
`DB/2`. It does not suppress damping simply because the hull passes through
level. No integral term or accumulated burst debt exists.

Only the drive with the matching effect sign can correct. Its authority fades
linearly with the current maneuvering command:

```text
priority = constrain(1 - maneuver_length / (ring_radius * MAN_LIM), 0, 1)
requested_amplitude = min(abs(demand), drive_MAX * priority)
```

For a normalized maneuver vector `m`, configured unit vector `u` and nonnegative
correction `a`, the continuous output is `centre + radius * (m + a*u)`.
Available ring travel is:

```text
headroom = max(0, -dot(m,u) + sqrt(max(0, dot(m,u)^2 + 1 - dot(m,m))))
```

Headroom also respects component PWM endpoints 1000..2000 us. Only the added
scalar is limited; the combined vector is not radially clipped or re-rotated.
Retaining maneuvering in the sum does not mean its physical effect is untouched:
an opposing correction can partially cancel it. MAX and MAN_LIM bound this tradeoff.

The final coordinates are rounded to integer microseconds. Ideal direction and
amplitude therefore have up to 0.7072 us of vector quantization error. The integer
point is checked against the ring and endpoints; if necessary the scalar is
reduced until a valid integer point is found. No change is made to an invalid
baseline: VRS reports `Baseline` and returns the existing limiter output verbatim.
This includes legacy limiter truncation that occasionally places a baseline just
outside its circle. VRS never repairs or clamps the original maneuver command.

A burst lasts at most ON_MS, including its normal amplitude ramp. Both drives
then share an OFF_MS interval without correction. Sign reversals cannot bypass
this interval. Rate/demand changes are evaluated throughout the burst. Normal
amplitude changes obey SLEW; disable, invalid input, lost attitude, sign reversal,
the pulse deadline and reduced physical/priority limits override ramp-down
immediately. Small corrections below PWM resolution may produce no rod movement.

## Parameters

There are 16 new parameters. Defaults are commissioning values, not a vessel tune.
The feature, both gains and both drive effect signs start disabled/zero.

| Parameter | Default | Meaning |
| --- | --- | --- |
| `VRS_ENABLE` | 0 | 1 enables the feature; any other value bypasses it |
| `VRS_P` | 0 | Ring radii per degree of roll error |
| `VRS_D` | 0 | Ring radii per degree/second of roll rate |
| `VRS_TRIM` | 0 | Target roll angle in degrees |
| `VRS_FILT_HZ` | 2 | Rate low-pass cutoff in Hz |
| `VRS_DB` | 0.02 | Absolute normalized demand threshold |
| `VRS_ON_MS` | 250 | Maximum burst window, milliseconds |
| `VRS_OFF_MS` | 250 | Minimum shared correction-free interval, milliseconds |
| `VRS_SLEW` | 1 | Normal correction slew, ring radii/second |
| `VRS_MAN_LIM` | 0.8 | Maneuvering fraction at which VRS fully yields |
| `VSP1_RS_ANG`, `VSP2_RS_ANG` | 0 | Fixed post-limiter correction angle, 0..359 degrees |
| `VSP1_RS_SIGN`, `VSP2_RS_SIGN` | 0 | Physical roll effect, -1/0/+1 |
| `VSP1_RS_MAX`, `VSP2_RS_MAX` | 0.2 | Maximum added displacement as a fraction of ring radius |

An invalid control parameter inhibits VRS instead of silently clamping it.
Live changes to these parameters cancel an ongoing burst, reset the filter and
require a new OFF_MS interval. On enabling or recovery from invalid input, VRS
also waits OFF_MS before its first correction.

The application has no arming state. VRS requires valid fresh EKF attitude,
healthy/fresh INS, a valid RC/override source, and valid routed X/Y/RPM input pulse
widths for the selected drive. A loop gap over 100 ms inhibits the current
correction and resets the filter. GPS position and absolute yaw are not required.

RPM_IN is a command, **not measured shaft speed**. Validity means a routed pulse
in 1000..2000 us; VRS does not infer that the rotor is turning, change RPM, or add
an engine-start function. Its gains describe rod displacement and need tuning
at the intended operating RPM. Existing maneuvering/RC-loss handling remains
outside VRS and is not replaced by a new vehicle failsafe.

## GCS telemetry

The existing `VSP_TEL_HZ` rate controls all values. Zero disables their transmission.
Disabled VRS emits none of the new keys. Existing `VSP1_XA`, `VSP1_YA`, `VSP2_XA`
and `VSP2_YA` still report the final component X/Y pulse widths; while VRS is on,
these include the correction. `SERVO_OUTPUT_RAW` reports downstream physical PWM.

All new values use the existing nonblocking `NAMED_VALUE_FLOAT` transport:

| Name | Meaning |
| --- | --- |
| `RS_ROLL` | Roll angle used by the controller, degrees |
| `RS_RATE` | Filtered body X angular rate, degrees/second |
| `RS_REQ` | Signed normalized PD demand |
| `RS_STATE` | 0 disabled, 1 waiting for valid input/configuration, 2 ready, 3 burst, 4 recovery |
| `RS_INHIB` | Combined inhibition/limiting bitmask below |
| `V1_RS_CMD`, `V2_RS_CMD` | Applied integer correction projected on its ray, divided by ring radius |
| `V1_RS_HRM`, `V2_RS_HRM` | Available geometric/endpoint headroom in ring radii |
| `V1_RS_DUT`, `V2_RS_DUT` | Active-command fraction of the last completed one-second window |
| `V1_RS_LIM`, `V2_RS_LIM` | Per-drive input/geometry/priority limiting flags |

Flag values are exact small integers even in a named float:

| Bit value | Meaning |
| --- | --- |
| 1 | Invalid/nonfinite attitude or unhealthy/stale INS |
| 2 | Invalid VRS configuration |
| 4 | Invalid RC/override source or missing/invalid routed driver input |
| 8 | Control loop gap over 100 ms |
| 16 | Demand in the deadband |
| 32 | Mandatory correction-free recovery interval |
| 64 | Maneuvering priority reduces authority |
| 128 | Ring travel, PWM endpoints or final integer rounding limit correction |
| 256 | Invalid baseline geometry, radius or centre |
| 512 | No configured drive can produce the requested roll effect |

These are commands and controller diagnostics, not measured thrust or shaft RPM.
Roll/rate are zeroed while inputs/configuration are invalid; consult RS_INHIB.
Duty summaries make short corrections observable at low telemetry rates. Thirteen
new values plus four existing coordinates are sent per reporting interval; choose
VSP_TEL_HZ to fit the link. Five Hz is a reasonable monitoring cadence, and faster
captures can help tuning when bandwidth permits.

## Verification and tuning

```sh
python3 Tools/Vektor2/tests/test_roll_stabilization.py
./waf configure --board sitl
./waf --targets bin/Vektor2
python3 Tools/Vektor2/tests/test_mavlink_vrs.py
python3 Tools/Vektor2/tests/test_mavlink_rc.py
```

The host test uses address/undefined sanitizers, both real VSP driver functions,
disabled-output regression cases, all 360 direction angles, circle/endpoint
constraints, timing, loss/recovery, live changes and an illustrative roll-decay
model. The MAVLink test checks all parameter names/defaults, real EKF gating,
simultaneous maneuvering, both effect signs, RPM passthrough, live disable,
telemetry silence when disabled, and RC-loss inhibition. The rover SITL model
does not model VSP hydrodynamics; these checks do not establish a vessel tune.

For commissioning, establish the two physical rays and effect signs first, then
measure actuator response and roll period. Start with P=0, low D and low MAX;
choose burst timing, slew and filtering that fit the measured response. Add a
small angle term only after rate damping works. Compare roll decay as well as
heading, lateral motion and maneuvering response: lateral thrust can produce
sway/yaw, and these two fixed rays cannot independently cancel all three motions.

## Code layout

- `RollStabilization.*`: pure controller, global burst timing, scalar allocation,
  integer output bounds and diagnostics.
- `RollStabilizationParams.*`: persistent parameter definitions and typed snapshots.
- `RollStabilizationBackend.*`: AHRS/INS/RC adapter and named-float telemetry.
- `VSP1.cpp` / `VSP2.cpp`: optional post-limiter correction and unchanged RPM path.
- `Logic.*`, `ComponentParameters.*`, `Telemetry.cpp`: small registration, cycle
  and telemetry hooks. No changes to the original limiter or routing algorithm.
